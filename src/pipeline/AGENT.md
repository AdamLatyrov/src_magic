# AGENT - граница разработки аналитического pipeline

1. Основная область правок - `src/pipeline`; публичный фасад - `src/main.py`, демонстрация - `src/main_notebook.ipynb`. `src/integration` принадлежит другому разработчику и меняется только по отдельному согласованию.
2. Не импортировать `src.integration`, не подключать к pipeline БД, очередь, S3 и настройки процесса. Integration создаёт и хранит задачу, загружает кадры и историю, выбирает продукт и версию каталога, собирает графовые настройки и провайдера.
3. Все решения, история, контракт, ограничения и проверки должны жить в `src/pipeline/documentation`; не полагаться на документы вне `src`.
4. Контракт `PipelineRequest` и `PipelineRunResult` синхронизировать с `main.py` и `main_notebook.ipynb`; `product_id` не добавлять без доказанной необходимости.
5. `run_id` сохранять в запросе, графе, callback, финальном DTO; кадры и ключи хранить в переданном порядке. Проверять экспертные решения `pending`, `approved`, `rejected`.
6. Не считать пустой перечень проблем успешным результатом без проверки статуса и деградации; после сверки пересчитывать оценки по **итоговому** списку проблем.
7. В callback передавать только сериализуемый безопасный снимок без изображений/сырого текста/секретов; callback синхронный, асинхронное хранилище - ответственность интеграции.
8. Не обещать устойчивое хранение, восстановление после перезапуска, retry с этапа, живую совместимость внешнего провайдера или production readiness без фактических испытаний.
9. Не сохранять секреты, сертификаты, необезличенные кадры или сырые логи в репозитории и ноутбуке; не удалять пользовательские файлы.
10. После изменений проверять Python-компиляцию, тесты, JSON/AST ноутбука, отсутствие `integration`-импортов и изменений вне `src`. Документировать точные команды и ограничения.
