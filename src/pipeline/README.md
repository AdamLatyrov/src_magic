# Пакет анализа

Pipeline получает готовый список скриншотов, проверяет пользовательский путь по критериальному каталогу, собирает находки, сопоставляет их с прошлым прогоном и возвращает итог.

## Публичный вход

`main.py` содержит фасад `AnalysisPipeline`. Для его создания нужны три готовых объекта:

- `GraphSettings` с параметрами этапов, путями к промптам и моделями;
- `CXCriteriaModel` с выбранной редакцией критериального каталога;
- провайдер, который реализует пять методов из раздела «Провайдер модели» в `documentation/contract.md`.

Для каждого прогона создайте `PipelineRequest` и вызовите `pipeline.start(request)`. Метод возвращает задачу. В приложении с работающим циклом asyncio дождитесь её через `await task`, чтобы получить `PipelineRunResult`.

Чтобы прочитать текущий прогресс, вызовите `pipeline.get_state_json(run_id)`. Это готовый словарь для ответа HTTP-обработчика. Снимки хранятся только в памяти текущего процесса. Интеграция должна сохранять их и итог самостоятельно.

## Состав

- `agent/` - граф и узлы анализа.
- `settings/` - настройки этапов и модели.
- `schemas/` и `dto/` - входные, промежуточные и выходные данные.
- `aef/patterns/gigachat_provider.py` - штатная реализация провайдера GigaChat.
- `dedup/` и `scoring/` - сверка прошлых находок и расчёт оценки.
- `tests/` - тесты логики и публичных контрактов.
- `documentation/` - контракт, руководство, ADR, обзор и журнал проверок.

## Документы

- `documentation/contract.md` - поля запроса, чтение состояния и формат результата.
- `documentation/pipeline_guide.md` - последовательность этапов и ответственность сторон.
- `documentation/adr.md` - решения, причины выбора и последствия.
- `documentation/review.md` - найденные при ревью свойства и ограничения.
- `documentation/verification.md` - фактические проверки и их пределы.
- `documentation/changelog.md` - заметки о текущих изменениях интерфейса.

Демонстрация вызова находится в `../main_notebook.ipynb`. Она использует демонстрационные данные; это не проверка качества модели.

Проверенные версии runtime-зависимостей и `ipykernel` записаны в `requirements.txt`. Пакеты для тестов перечислены в `requirements-test.txt`. Зависимости сервиса из `integration` задаются его средой развёртывания отдельно.
